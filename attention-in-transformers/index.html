A transformer layer has to let every token in a sentence read from every other token. Attention is how that happens. Each token poses a question about what it needs, every token advertises what it holds, and the answer is a weighted average over the whole sentence. There is no recurrence and no convolution. The only thing connecting one position to another is a matrix of weights the model recomputes for every input.

The whole thing fits on one line, \(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\), and the two widgets below run it end to end on a short sentence: \(d_{model} = 32\) split across 8 heads, so \(d_k = d_v = 4\) inside each head. The first walks a single token through the computation; the second shows the finished weights for every token at once. One caveat before you read anything into either: the Q, K and V vectors here are drawn at random rather than learned, so which word attends to which carries no linguistic meaning. The mechanics are faithful; the pattern is noise. Everything below the widgets explains the pieces.

Queries, keys and values

Start from a sequence of embeddings \(X \in \mathbb{R}^{n \times d_{model}}\) and three learned projections of it:

\[Q = XW^Q, \qquad K = XW^K, \qquad V = XW^V\]

Same input, three different views. The names come from a database lookup, where you match a query against keys and retrieve the value that matches:

VectorBelongs toWhat it encodes
query \(q_i\)the token doing the readingwhat this token is looking for elsewhere in the sentence
key \(k_j\)the token being readwhat this token offers, used only for matching
value \(v_j\)the token being readthe content actually handed over once it has been matched

The difference from a database is that attention never picks a single match. It matches softly against every position at once and blends the results. Keeping keys separate from values is what makes that blend useful: a token can be easy to find for reasons that have nothing to do with the information it passes on. Those are the three vectors in the Q, K, V table above, four numbers each because \(d_k = d_v = 4\) in this head.

Scoring, and why the scores get divided

Similarity is a dot product, so all \(n^2\) comparisons are one matrix multiply:

\[S = \frac{QK^\top}{\sqrt{d_k}}, \qquad s_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}}\]

Entry \((i,j)\) says how strongly token \(i\) wants to read from token \(j\). That is the left-hand matrix above, and it is small enough to check by hand: take any token's Q row from the vector table, any token's K row, dot them, divide by \(\sqrt{4} = 2\). The result is \(n \times n\), which is where the quadratic cost in sequence length comes from, and most of the long-context literature is about avoiding ever materializing it in full.

Read it by row, never by column, and notice it is not symmetric. A token can attend heavily to a neighbor that pays it no attention back, since \(q_i \cdot k_j\) and \(q_j \cdot k_i\) are different numbers computed from different projections.

The \(\sqrt{d_k}\) needs justifying. If the components of \(q\) and \(k\) are independent with mean 0 and variance 1, then their dot product sums \(d_k\) such products and has variance \(d_k\). Raw scores therefore spread out as the head gets wider, and a wide spread drives softmax into a near one-hot corner where the largest score takes almost all the weight and the gradient through the others goes flat. Dividing by \(\sqrt{d_k}\) returns the variance to 1 and keeps the distribution in a range where it can still be trained.

Softmax turns scores into a mixture

Softmax is applied along each row:

\[A = \mathrm{softmax}(S), \qquad a_{ij} = \frac{e^{s_{ij}}}{\sum_{j'} e^{s_{ij'}}}\]

So every row sums to 1 and row \(i\) is a recipe for rebuilding token \(i\) as a convex combination of value vectors:

\[\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V\]

That is the right-hand matrix above: the same information as the left one, now non-negative with every row summing to 1. Columns sum to nothing in particular, which is why a column is a question about demand for a token rather than a distribution over anything.

Note which vectors those weights multiply. Q and K only ever decide how much, by producing the scores; V decides what actually travels. A token can score high on everyone's query and still contribute little content if its value vector is small, and the two jobs are learned by separate matrices precisely so they can disagree.

Exponentiation also exaggerates. A score gap of 2 in the left matrix becomes a weight ratio of \(e^2 \approx 7.4\) on the right, so softmax sharpens an ordering that already existed in the raw scores. That amplification is the reason the \(\sqrt{d_k}\) division matters as much as it does.

Eight heads instead of one

A single attention pattern per layer is a bottleneck, because one distribution per token has to serve every kind of relationship at once. Multi-head attention splits \(d_{model}\) into \(h\) slices of width \(d_k = d_{model}/h\), gives each slice its own \(W^Q, W^K, W^V\), and runs the same computation independently in each:

\[\mathrm{MultiHead}(X) = \mathrm{Concat}(\mathrm{head}_1, \dots, \mathrm{head}_h)\,W^O\]

Because the slices are narrower, the total cost stays close to a single head at full width, and the concatenated outputs get mixed back together by \(W^O\). In a trained model the heads end up doing visibly different jobs, with some tracking the previous token, some following syntactic dependencies, some doing very little at all and prunable without much loss. Switching heads in the widget only resamples random vectors, but it does show the structural point: eight independent \(n \times n\) patterns over the same sentence, computed in parallel.

What this leaves out

The widget shows encoder-style self-attention, where every token may read from every other. A decoder adds a causal mask, setting the upper triangle of \(S\) to \(-\infty\) before softmax so position \(i\) sees nothing after itself, which is what makes next-token training possible in one pass. Cross-attention changes the sourcing instead, taking \(Q\) from one sequence and \(K, V\) from another.

The larger omission is position. Attention as written is permutation-equivariant: shuffle the input tokens and the rows and columns of \(A\) shuffle with them, leaving every weight otherwise unchanged. The mechanism genuinely cannot tell "the cat sat" from "sat the cat", so word order has to be injected separately, either added to the embeddings as sinusoidal positional encoding or applied inside the attention computation as rotary embeddings.
